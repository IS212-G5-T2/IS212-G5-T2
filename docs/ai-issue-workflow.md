# AI Issue Workflow

The canonical, executable workflow for Jira implementation work is [`.ai/workflows/jira-ticket.md`](../.ai/workflows/jira-ticket.md). It defines source retrieval, Confluence test-case discovery, agent-stage boundaries, approval gates, branching, pull-request progression, failure handling, and recovery.

This document is the durable human-facing pointer for contributors who encounter older references to an “AI issue workflow.” Jira remains the planning source of truth; GitHub owns branches, commits, pull requests, and CI; Jira automation owns the documented status transitions. Do not duplicate Jira stories as GitHub Issues.

For AI-assisted work tracking, see [`AI_USAGE.md`](../AI_USAGE.md). For CI ownership and component test entrypoints, see [CI process](ci-process.md).
