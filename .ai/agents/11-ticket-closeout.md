# Ticket Closeout Agent

Run in a fresh subagent context only when the user explicitly says a specific ticket is finished and asks to close its branch or archive its chats. This is a later, conditional stage, not part of implementation. A separate closeout chat lets implementation chats become idle. Do not fetch Jira or Confluence pages; use the ticket key, Git/PR state, and `.ai/runtime/{ticket-id}/conversation-registry.json`.

1. Confirm the exact ticket and branch. Check the PR/merge state, working tree, and ongoing ticket work. Do not archive a chat that is still running or needed for an open review; report incomplete delivery instead of silently treating it as done. Do not mark Jira `Done` or change Jira status.
2. Read the private registry and list available provider chats. If the ticket predates this registry or the file is missing, create it from verified discoveries and report the incomplete history. Verify missing chats through project/branch metadata and minimal title/turn summaries; do not open private attachments or case content. A title or ticket-key substring alone is insufficient. Exclude shared, multi-ticket, unrelated, or uncertain chats. A registry is local to its checkout: inspect other known ticket worktrees/registries when accessible, and report incomplete discovery.
3. Distinguish a user-facing chat/thread ID from an internal subagent ID. Record both when available. Without an exposed persisted thread ID or archive capability, a subagent cannot be archived separately; report it. For Codex, archiving a parent thread may also archive descendants; inspect descendants before archiving a parent so unrelated work is not hidden.
4. Archive verified, idle, persisted ticket chats and persisted subagent threads with the provider's archive tool; never delete transcripts. Verify each result, then set `archivedAt` in the registry. If the tool is unavailable, report pending rather than claiming success. Archive the initiating chat only once idle and safe; if it is still running, leave it pending and report how to finish that last archive.
5. Write private `.ai/runtime/{ticket-id}/closeout.md` with branch/PR state, archived IDs, pending IDs and reasons, unarchivable subagent IDs, and any remaining Git cleanup. Do not include private contents in public documentation or the PR.

If the closure request includes closing or deleting the branch, first verify the exact branch is merged or explicitly abandoned and that no dirty or unpushed work would be lost; use the repository's safe worktree/branch cleanup process. Never delete an unmerged or uncertain branch. Do not stage, commit, push, create a PR, or rewrite history during chat archiving.
